# Bien dong Phat trien Khu vuc: Do luong toc do "Be tong hoa" dai du an San bay Long Thanh & Vung phu can (2018–2026)

Land-cover classification and built-up (concrete) expansion analysis around
Long Thanh International Airport, Dong Nai, Vietnam, using multi-temporal
Sentinel-2 imagery (2018–2026).

Full project pipeline:

```
Satellite Images -> Data Preprocessing -> EDA -> Training Samples ->
Random Forest Classification -> Accuracy Assessment -> Change Detection ->
Built-up Area Analysis -> Buffer Analysis -> Concrete Expansion Rate
```

## Current status: Phase 1 (Data Preprocessing + EDA)

This repository currently implements **Phase 1 only**: data validation,
preprocessing (missing/invalid-value handling, optional cloud masking, AOI
clipping), spectral index calculation (NDVI/NDBI/NDWI), and exploratory data
analysis. Random Forest training, accuracy assessment, change detection and
expansion-rate analysis are out of scope until Phase 2+.

**No satellite imagery has been added to this repository yet.** The pipeline
code is complete and has been verified end-to-end against a synthetic test
raster (`pytest tests/test_pipeline_smoke.py`, 6/6 passing), but
`python scripts/run_pipeline.py` currently produces a data-availability status
report rather than fabricated results — see
[`reports/Phase_1_Data_Preprocessing_and_EDA.md`](reports/Phase_1_Data_Preprocessing_and_EDA.md)
for the up-to-date status, and [`data/raw/README.md`](data/raw/README.md) for
exactly what to add to activate it on real data.

## Adding data and running the pipeline

1. Read [`data/raw/README.md`](data/raw/README.md) for the exact expected file
   layout (one 6-band GeoTIFF per year, band order `B2, B3, B4, B8, B11, B12`).
2. Place imagery under `data/raw/`, optionally an AOI boundary
   (`data/raw/aoi_boundary.geojson`) and/or labeled training points under
   `data/samples/` (see [`data/samples/README.md`](data/samples/README.md)).
3. Run either:
   - `python scripts/run_pipeline.py` — regenerates all figures, CSV
     statistics, per-year QC reports, and the Markdown report from the real
     data, or
   - `jupyter nbconvert --to notebook --execute --inplace notebooks/01_preprocessing_eda.ipynb`
     — regenerates the interactive notebook with real outputs, or open it in
     Jupyter and run cells interactively.

Both entry points use the same `src/` modules and will never fabricate a
number: any missing input (imagery, AOI, training samples) is reported
explicitly as a limitation instead of being assumed or faked.

## Tests

```bash
pytest tests/test_pipeline_smoke.py -v
```

Builds a small synthetic raster + AOI + training points in a temp directory
and exercises validation, preprocessing, feature engineering and
visualization end to end — this is what currently verifies pipeline
correctness in the absence of real imagery.

## Design notes

- **Reusable across years:** every function in `src/` takes `year` as a
  parameter and is driven by `src/config.py`, so adding a new year is just
  adding a new `data/raw/<year>.tif`.
- **Memory-bounded:** raster statistics are computed via chunked/windowed
  reads; the tabular feature dataset is built from a fixed-size random sample
  drawn with a streaming reservoir sampler
  (`src/preprocessing.py: ReservoirSampler`) so a full-resolution multi-band
  scene is never loaded into RAM.
- **Reproducible:** all random sampling is seeded (`src/config.py: RANDOM_SEED`).
- **No silent data loss:** missing/invalid/cloud/outside-AOI pixels are
  counted and reported at every stage rather than dropped quietly.
